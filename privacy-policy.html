1.Data Processing and Core Functionality

We adhere to strict data minimization principles. To deliver real-time network insights, detect unauthorized devices, and alert you to potential wireless intrusions, the Application requires operational access to localized network configurations.

Localized Technical Data

To establish a stable connection and run perimeter analysis, the Application processes:

  • Service Set Identifier (SSID): used to identify and catalogue your current wireless network environment.
  • Basic Service Set Identifier (BSSID): used to detect specific hardware access points and map local infrastructure.
  • Internet Protocol (IP) Address: used to coordinate local device discovery, check routing loops, and run latency diagnostics.

WiFi Intruder & Network Device Discovery

To flag unknown network participants, verify hardware assets, and construct custom access rules, the Application scans your Local Area Network (LAN). This security operation processes:

  • Media Access Control (MAC) Addresses: processed on-device to uniquely distinguish separate hardware units communicating over your network topology.
  • Device Hostnames and Manufacturer Signatures: analysed to translate raw hardware indicators into human-readable device names (e.g., recognizing an unrecognized smartphone vs. a smart thermostat).
  • User-Defined Trust Profiles: saves your manual categorizations, such as marking a device explicitly as “Verified,” “Unverified,” or “Intruder.”

Our Local-First Principle

All localized network signatures, discovered MAC addresses, and user-compiled “Verified/Unverified” device lists are processed and stored entirely within your physical device’s sandboxed local storage. This operational data is never transmitted to, stored on, or harvested by external Kizuna Software Solutions corporate servers. Your domestic or enterprise network blueprint remains strictly yours.

The one narrow, opt-in exception to local-only processing is the AI Insights feature, described immediately below in Section 2. If you never enable AI Insights, no network or device data described in this section ever leaves your device.

2.AI Insights (Opt-In Feature)

WiFi Intruder Alerts includes an optional “AI Insights” feature that generates plain-language explanations of a device’s likely identity, risk score, or possible spoofing behaviour. This feature is off by default and only activates if you explicitly enable it in Settings.

When you turn AI Insights on, the Application sends a limited, purpose-built snapshot of the specific device or network you are viewing — such as MAC vendor/manufacturer signature, hostname, IP address, open ports, and the risk/trust signals already computed on your device — to Groq, Inc., a third-party AI inference provider, over an encrypted (HTTPS) connection, solely to generate a natural-language summary. No account information, personal identifiers, browsing history, or data from other apps on your device is ever included in this transmission.

The AI Insights feature is a best-effort explanation layer only: it never determines trust status, never calculates the numeric risk score, and never independently declares a device to be spoofed. Those determinations are made entirely by deterministic, non-AI logic running on your device; the AI only explains what that logic already concluded. If the AI request fails for any reason, every other feature of the Application continues to work unaffected.

You may disable AI Insights in Settings at any time. Doing so immediately stops any further device or network data from being sent off your device for this purpose.

3.Advertising & Marketing Policy

WiFi Intruder Alerts is entirely ad-free. We do not integrate with third-party ad brokers, serve commercial banners, or profile your application behaviours for marketing metrics. Consequently, the Application does not track, request, or handle your device’s Google Advertising ID.

5.Log Data

In the event of an abrupt application crash or runtime error, the Application collects diagnostic crash telemetry (via secure platform debugging tools) generated by your device. This data is known as Log Data and contains:

  • Your device’s model name, manufacturer, and core hardware architecture.
  • Operating system version and system state configuration at the exact time of the exception.
  • Execution metrics, timestamps, and stack traces associated with the system event.

We use these logs exclusively to isolate software bugs, optimize resource allocation, and roll out performance updates.

6.Storage and Local Databases

WiFi Intruder Alerts does not utilize tracking cookies. The Application relies on native device storage mechanisms (such as encrypted SQLite or platform SharedPreferences) to retain your verified device profiles, intruder filters, and custom preferences locally.

You can manage storage permissions via your mobile operating system settings at any time. Please note that clearing the Application’s cache or data via system settings will permanently erase your locally compiled device verification lists.
